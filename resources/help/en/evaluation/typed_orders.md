## 📊 Evaluation: Typed orders

<b>Typed orders</b> reads the value of a list of orders you type in, directly off one <b>rpm-tracked [spectrogram](topic:spectrogram/intro)</b> -- the one Evaluation that reads a 2D map instead of a curve. For each order, the row's value and rpm equal what [Order Tracking](topic:order_tracking/intro)'s <b>Max</b> would give for an [order cut](topic:order_tracking/orders) computed with the exact same [FFT](topic:shared/fft_size), [window](topic:shared/windows), step and order width: the spectrogram's matrix (energy per bin) already holds the same physical energy an order cut would integrate, so this reads it back out instead of recomputing anything from the raw measurement.

- <b>Orders:</b> A list separated by commas or semicolons, e.g. <code>1, 2, 4.79</code> or <code>1; 2; 4.79</code>. The decimal separator is a dot; a zero, a negative or an unreadable entry makes the whole list invalid. Every listed order gets exactly one row -- never zero, never more than one -- the same "always a row" rule Max follows.
- <b>Order width:</b> The order band width &Delta;O used for the moving-band integration, same meaning and default (0.2) as Order Tracking's own Order Width. It is this Evaluation's own parameter, not read from the Order Tracking ribbon -- the table has to be reproducible from its own settings even if the ribbon is changed afterwards or the dock came from a different tab. The used width is shown next to each order in the Order / Band column, e.g. "Order 4.79 (&plusmn;0.2)".
- <b>"&mdash;" (dash):</b> An order that falls entirely above the file's Nyquist frequency, or entirely below the FFT's frequency resolution, still gets a row -- just an empty one, exactly like Max on a curve with no valid sample.
- <b>Spectrogram against time:</b> A spectrogram tracked against time, not rpm, has no order to read (an order needs a shaft speed axis) -- it offers no rows, so the card shows its usual "no curves supported" message rather than a table of dashes.
- <b>Which docks:</b> Only a spectrogram dock's own rpm-tracked waterfall. A dock showing order cuts, spectra or Overall Level curves offers this Evaluation too, but its table stays empty for it -- use Max or Top-N maxima there instead.
- <b>Amplitude, Units, Sorting, Copy/Export, Columns&hellip;:</b> Same as the [Max Evaluation](topic:evaluation/max) (see its help topic). Format (Linear/Power/PSD) stays disabled: a Typed orders row is always a Linear amplitude, the same convention [Order Tracking](topic:order_tracking/intro) uses.
- <b>Respect Trace filter:</b> Has no effect here -- a spectrogram dock has no per-trace mask to respect (it draws one image, not a curve list).
